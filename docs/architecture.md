# v3.0 候选版技术设计

2026-10-02新增 [统一检索流水线一期](retrieval_pipeline.md)：SearchProvider与已知URL Fetch分离，免费/计费入口分离，供应商独立熔断，共用原行动账本及证据关系。下文Tavily密钥流程为旧检查点兼容说明；新运行默认使用keyless且不隐式启用计费入口。实时服务与研究质量收益尚未验证。

## 边界

当前版本保持单机 Python + SQLite 架构：候选发现可在任意日期由用户发起，受控公开来源先进入跨日发现队列，再由可审计模型分批初筛；超过新鲜度期限时采用零模型增量复核。深研和正式写作仍由人工与Codex协作完成，再由程序执行证据闸门、确定性DOCX导出和人工审核状态登记。不建设批量全文抓取、自动定时任务或自动对外报送。

## v3.0 契约与兼容

版本为 `3.0.0rc1`。`candidate_eligibility` 在原筛选调用内附带 `candidate_shadow_v1`，保存于 `Candidate.eligibility` / `candidates.data_json`；`candidate_review` 任务保存回源推荐和材料版本。`_rank_candidates`、`candidates()`、`candidate_pool()` 仍按现有综合分排序。旧 `legacy/fact_first_v1` 输入恢复原提示，新契约冻结提示、Schema、模型配置及输入，避免升级后重复调用。

`research_v3` 预研按停止/继续分类，复用 `research_reviews`；`problem_mechanism` 校验解释和证据引用。`research_brief` 使用 `tasks` 保存单一深研内容，JSON/Markdown为可重建副本，按内容哈希保留版本。写作输入关联最新预研批准、证据哈希、问题解释、基线/最低干预及选择理由；`no_draft` 保持不成稿。

`research_stops` 在发现入池、旧待筛队列和提供商入口前读取真实停止结论，直接以既有记录为准，不迁移或回填历史数据库。人工停止另在 `tasks.kind=research_stop` 保留不可变快照，后续改批准字段也不能抹去停止依据。匹配以原始来源、明确转载入口及具体问题材料为依据，不按主题词封禁。重开绑定发现陈述哈希、停止记录、新版预研的已读主张和新的人工确认；仅程序字段通过不等于关键证据质量通过。每轮 `research_stop_gate.json` 记录停止与重开依据，冻结输入包含已停止题或重开依据变化时不能继续提供商调用。

数据库结构版本由 0 迁至 1，仅给 `claim_sources` 增加可空 `evidence_detail_json`。旧指纹明确列举旧字段，空新列不使旧审查失效；`evidence_v2` 指纹纳入关系级摘录和支持范围。来源用途元数据保存内部契约标记，导入不能降级。研究简报哈希追加到新版内容审查键和导出键，未使用新版简报的旧键原样保留。迁移备份和实测结果见实施验收记录。

`semantic_review` 默认只准备原文输入，显式启用后经 `CallLedger` 调用 provider；来源及主张先逐条后组合检查，输出支持关系和问题代码。影子意见及原文裁决分别保存于 `semantic_evidence` / `semantic_adjudication` 任务。失败状态不改写事实。语义动作按 `deep_research:TOPIC_ID` 记账并与本题 `stage_usage` 共用深研上限；先有模型调用时，阶段估算只补足上限余量；已有估算不释放。真实调用、切换排序及质量收益均不由离线测试推定。

`replay` 为现有回放脚本增加不可覆盖的清单和内容哈希；可知时间/依据不足标 `incomplete_replay`，不借当前配置补齐。包内预研评估只运行确定性规则，不执行模型，不宣称端到端 A/B。操作与数据示例见 [v3.0 工作流](v3_0_workflow.md)。

## 模块

- `config`：TOML 配置和路径解析。
- `db`：SQLite 历史库、运行库、来源库、模型调用审计库。
- `workflow`：六阶段状态机、幂等候选生成、人工闸门、暂停和恢复。
- `model_calls`：扫描和诊断共用的调用前占额、失败记账、结果与任务事务落库，以及单运行JSONL审计副本。
- `delivery`：零模型稿件检查、四项审查记录、源稿/证据/导出版本绑定；复用tasks，不新增审查服务。

第三批增量：`delivery_events` 仅记录每题首次通过新送审闸门的实际导出，和topics、导出任务同事务提交，不回填无证据的历史事件。首次事件时间不随修订移动。产量统计从全部live运行读取完成事件，以北京时间自然周归属；窗口外发现、窗口内完成的题不会漏计。转化归因仍按发现周单列，不能拿该口径证明每周实际交付能力。

`draft_quality_review` 任务以课题ID、源稿SHA256和证据SHA256作为输入键。证据指纹覆盖本题主张、来源关联与本题来源用途元数据。四项记录必须明确审查者、结论、理由、时间和覆盖的核心主张/问题编号；字段齐全只证明记录存在，不证明语义判断正确。`draft` 和 `approve` 重新检查版本及确定性规则；已确认新流程稿在 `mark-submitted` 前核验最终文件与批准导出哈希。旧已批准记录保留兼容，不自动撤销、不虚构补审。

发现来源增加两个限量官方HTML目录适配，和RSS复用缓存、元数据解析与漏斗；目录按链接白名单前缀及显示日期提取，无正文递归请求。URL规范化保留文章身份参数并规范参数顺序。制度覆盖仅用当前适用辖区且已生效的机制；查询异常和异地比较信息不触发覆盖扣分，核验失败与未查到覆盖均不等于制度缺失。候选前影子审查仍不强制执行。

`collector` 在读取 RSS 缓存和写入新缓存前校验 XML 与 `rss/channel` 结构，目录 HTML 不受该校验影响；无效新响应不入缓存，旧异常缓存不自动删除或重抓。批量发现将错误写入来源漏斗；`search_query` 将解析失败抛给制度新意及影子审查的错误分支，只有有效的空 RSS 才返回成功空列表。此修复只纠正获取状态，不修改既有审计、政策判断、候选排序或来源健康阈值。

2026-09-20 目录试验复用 `html_index` 的缓存、日期过滤、去重和漏斗，新增三个来源，不修改评分与模型预算。`listing_format=haidian_medical` 仅把明确匹配的静态脚本链接转换为锚点，其他脚本分支不解释、不执行。目录预检允许同站点的跨栏目文章前缀（如欠薪专题引用公示公告），必须是 HTTPS 且与目录同域；实际条目继续受显式 `item_url_prefix` 限制。每目录最多 15 条，原始链接保留，未为发现阶段新增正文抓取。

发现体系重构一期增加4个已验证栏目，共9个 `html_index`。法院日期只适配已核验的 `i.date` 标签；公开答复目录日期标为 `listing_displayed_date`，来信和答复日期须回源分别核验。Bing共用入口在每次采集开始重置故障状态，先执行一条RSS查询，只有明确HTML响应才停止同轮重复RSS请求，保留每条跳过状态及错误原因。其他来源并行继续；超时、空RSS和一般XML错误不触发整组停止。该行为不持久停源、不改信源等级。

`discovery_coverage` 将渠道、发布域名、材料类型、日期依据放入 `EventItem.material.discovery_provenance`，复用现有JSON持久化，不迁移SQL结构。覆盖报告对URL去重，不声称是独立来源链；旧记录缺字段按unknown显示。规则合格与实际模型输入分别观察，未送模型时后者为0。关闭Tavily、离线fixture及已完成采集恢复也能输出覆盖文件，不为补报表重发搜索。

Tavily可选查询角色在现有总调用上限内每角色选一条；未配置时完全沿用旧逻辑，恢复只使用已冻结查询。当前未启用角色配置，未降低advanced深度，未接入无凭据的新服务。Token调整遵循用户2026-09-20授权，以任务必要性和质量为依据扩大，并保留预算调整及结果复盘账，不将该授权转换为搜索API无限额度。

- `budget`：默认全流程Token观察；可显式恢复额度政策，付费与次数边界独立。
- `materials`：零模型用途、日期、疑似推广及同源提示；定向摘录保留位置、条件和版本风险，不替代内容核验。
- `tavily`：仅Search/Extract的可选客户端；固定HTTPS端点、不携带登录态；调用前SQLite事务占积分及等价费用，失败保守记账，成功精简结果可缓存。
- `retrieval`：发现层有界场景补充，以及人工选题后的固定检索问题单；用途分离、检查点、原输入恢复，不自动研究或写作。
- `document`：从保留的参考 DOCX 创建显式样式模板并导出正式结构。
- `snapshots`：按人工点名固化易变化的核心公开证据及内容哈希。
- `cli`：本地命令入口。

## 数据模型

`runs` 保存检查点；`tasks` 保存版本化任务和幂等结果；`candidates` 保存候选与分项理由；`topics`、`sources`、`claims`、`claim_sources`、`research_reviews` 保留历史、证据与批准。`model_calls` 分列程序请求实报、预留/估算及费用；`stage_usage` 保存主对话初筛、预研、深研和写作的声明或产物代理估算，不把未知记成官方统计，已有记录不向下清零。发现队列、来源漏斗、影子审查和预算调整历史继续使用原表。新对话路径复用tasks和stage_usage，不迁移或重写历史数据库。

## 有限预研决策闸门

### 可选检索的独立边界

发现层先完成原有四层RSS/目录采集，保存 `collection_checkpoint.json`（原始元数据、来源统计、冻结的最多4条补充查询及日期），再逐条调用Tavily `news`。恢复不重取RSS或混入新查询。结果按发布域名而非查询词归并来源；缺日期是待核，不用更新时间伪造发布时间。用途/推广/转载提示只增加输入语义，不将影子原始信源或政策覆盖审查升级成硬规则。模型池大小和Token预算不变。

`retrieve`问题单绑定运行和已选候选，正式研究额外核对最新 `research_reviews` 的人工放行。`policy/general`不带新闻日期限制；新事件才使用90天窗口。Extract只接受目标页及目标词、普通HTTP失败或不完整的原因；不自动递归抓取、渲染浏览器或规避登录限制。响应不超过配置字节数，完整有界响应在内存选择目标和限制性上下文，落库只留摘录/哈希/位置/警告。

`retrieval_calls`单独记录action、请求哈希、状态、预留/供应商报告/记账积分、等价费用、错误码、缓存来源和精简响应。与 `model_calls`、Token分列，未知用量不归零；Extract供应商报告0但有成功页时保留分摊费用。请求前 `BEGIN IMMEDIATE` 占额，行为文件锁防并发双发；同输入成功结果优先复用，同输入失败只有显式重试且原预算允许才再请求。问题单使用 `tasks` 和原子JSON检查点；诊断为独立mode，不写候选、证据、历史或周产量。按原渠道的滚动反馈评价收益，不新增专用评估平台。

有界补查使用可选`repair`字段绑定最新预研决策及关键未知；轮次分开保存检查点，但请求账本沿用原action，不扩大搜索数、积分或费用上限。`source_trace`给预研报告保留摘录、适用限制与逐主张的获取状态诊断，正式证据闸门拒绝未读来源和无支持的辅助事实。人工审批、预检和送审登记均核对候选最新版本，旧题放行不可继承。兼容旧摘录时不自动补造抓取成功。详细字段、边界、回放及回滚见`docs/research_workflow_revision.md`；不增加数据库结构或模型调用。

人工选题后、深研前先生成小型结构化决策单。决策单明确区分已验证事实、基于证据的推断、未验证假设和分析判断，并记录最强反证、替代解释、关键未知、放弃条件、置信度、北京或海淀权限边界、定向研究问题和本阶段预算理由。`proceed` 与 `reframe` 仅代表结构化检查允许提交人工复核；存在阻断性关键未知时即使人工命令也不能越过。只有最新决策单的 `human_decision=proceed` 才能解锁对应运行、候选和题目组合。

每个初步机制以内部卡片记录行动主体、对象、触发条件、信息、成本承担、受益者、预期行为、规避、成本转嫁、核验、纠错、退出和更低成本替代方案，并分别压力测试基线、最可能和不利情形。该卡片不直接进入正式稿，避免正文任务蔓延。

## 证据质量闸门

主张使用课题内 `local_id`，旧全局 `id` 保持不变；新课题发生同名时生成隔离的内部编号。来源URL与内容哈希仍可共用，但每题的完整来源元数据写入 `source_usages(topic_id,source_id)`，评估只读取本题记录。导入在一个事务内更新本题来源用途、主张和关联，失败则回滚。历史迁移只增加字段、索引和用途快照，不重写旧来源和关联；跨题共享的旧来源由于历史用途可能已被覆盖，迁移快照标记 `needs_review`，只有本题重新核验导入后才解除。迁移不能推测或还原已丢失的信息。

只有一、二级来源且非 `pain_signal` 的有效信息链参与事实验证。统计口径值必须是非空文本；所有主张的无效认识分类都阻断。来源核验日期必须显式提供，不能用导入时间替代；未来核验日期无效。上述确定性检查不替代事实和机制内容的实质审查。

深研不再只统计网页数量。每个关键主张都记录 `origin_group`：转述同一发布会、原报告或数据库的页面只算一个来源链。关键主张可由一个正式一级原始来源支撑，或由至少两个独立来源链交叉验证。零主张、零核心主张一律阻断；多个独立来源链优先标记为交叉验证，避免误报为“单一权威来源”。

制度新意主张还必须完成现行法规、政策、司法建议和主管机制覆盖审查。正式证据包中的主张需标注 `verified_fact`、`evidence_based_inference`、`unverified_hypothesis` 或 `analyst_judgment`。未分类主张、未验证假设和分析判断不能直接进入正文；核心主张还需保存置信度、截至日期、不确定性、可证伪条件和来源最近核验时间，核心统计需保存时间、地域、总体、单位和定义。状态为 `single_source`、`conflicted`、`needs_review` 或 `rejected` 的关键主张会阻断正式写作。详细元数据只在正式研究证据包强制，不把候选阶段升级成重型档案。系统允许深研结论为“不成稿”。

动态网页只在正式研究实际使用、内容容易变化且人工点名时固化。`evidence-snapshot` 从证据包读取来源URL、摘录和正文用途，保存PDF或HTML、抓取时间、最终URL、SHA-256及文件大小；不携带登录态，不把稳定法规和普通页面批量快照化。相同来源和相同内容哈希幂等复用。

## 候选阶段制度新意快审

模型初筛不再直接产出最终5题，而是最多产出8个备选并为每题记录 `gap_hypothesis`、`gap_type` 和最多2条 `counter_queries`。`novelty` 模块先查已核验的本地政策机制库，再在真实运行中完成最小化的标题、摘要反证检索。区级 `site:` 查询会保留原查询并追加覆盖北京市和中央官方域名的跨层级查询；反证政策使用独立的730天窗口，不受候选新闻90天窗口限制，命中后先标记覆盖风险而不据此认定政策仍然有效。

自动阻断采用不对称规则：仅 `policy_absence` 类主张被本地已核验机制直接覆盖时标记为 `covered / block_original_gap`。执行、效果、协同和问责类主张即使命中既有机制，也只标记为 `likely_covered / keep_with_novelty_warning`，不自动删除。检索无结果只能得到 `unclear`，不能证明制度不存在。

`novelty_audits` 保存每次快审、决策、反证、复核结果和代理Token指标。有效预研通过候选中的事件ID回连快审记录，并按标准化 `decision_reason` 自动写入 `confirmed_block`、`confirmed_warning`、`false_block`、`missed_coverage`、`reframed`、`supported_gap` 或 `stopped_other`；已经存在的人工复核理由优先，自动反馈不得覆盖。每次扫描都会重新计算滚动21天指标。自动结论增加 `improve_early_coverage_detection`，用于样本量足够且后续预研发现早期漏判时提示修正规则。阻断准确率只使用能判断阻断正确或错误的标签，不把“改写”或其他停止原因混入分母，也不使用系统自己的阻断结果循环证明自己正确。

## 候选100分评分与自然周产出漏斗

规则初筛分只负责在模型调用前压缩事件池。正式候选分由 `[scoring]` 的八项正向权重计算，再扣除 `[penalties]` 及制度新意快审扣分；权重合计不是100时 fail-closed。海淀事件取得海淀分后不再重复取得北京分，时效分由发布时间确定，其余判断分由结构化初筛结果提供并受配置上限约束。候选 `score_reasons` 保存每项得分、满分、理由、扣分键、扣分值和依据，最终按综合分排序；旧模型缓存缺少新字段时按零分处理相应判断维度，不会回退使用规则分冒充综合分。

滚动质量报告按真实运行的发现周建立自然周 cohort，把后续选择、预研、深研、证据闸门、成稿、人工通过和实际报送归回该运行所在周，避免同一材料跨周处理时重复计数。报告保留每周停止原因、预研停止率、每篇证据闸门通过稿所需候选数和项目已记录Token。默认展示当前周加最近4个完整周；稳定产出只评价已经结束的4个自然周，漏跑周以零计，当前未结束周不提前计为失败。由于交互式Codex订阅通道可能不提供精确Token，报告显式区分项目账本记录量与不可计量部分。

## 模型调用前的去重与复用

`run_context` 区分 `live`、`test_fixture`、`mock`、`diagnostic` 和 `replay`，只有 `live` 运行进入历史排除和21天质量指标。规则筛选后的模型输入池会先核对历史URL、“标题+发布日”，以及“同日、同发布机构、同核心主题”的跨站转述，未变化或同源事件不进入模型。完整输入哈希相同时，`tasks` 跨运行复用已完成结果。缓存查找发生在预算预留和提供商初始化之前，因此零成本复用不受当前预算或备用密钥状态影响。

真实初筛、显式语义复核和诊断只接受本次 `--model` 明确值，不从固定配置回退。`Settings.selected_model` 仅在内存携带；CLI无法可靠读取UI选择，缺参时先于运行初始化和采集停止。初筛冻结材料、检查点和调用账本保留选择；完成缓存不改原模型，新契约冻结选择不同则禁止新调用，旧冻结模型名不能覆盖新传入值。CLI不强制思考深度，也不改全局设置。交互产物的估算只登记传入值或 `unknown`，不宣称已核验会话实际模型。

每次扫描使用四层发现池：第一层为海淀和北京主题源，第二层为北京法院、检察、市场监管和权威媒体，第三层为全国部委、监管、司法、统计和调查源，第四层为投诉、论坛和社交平台待核线索。扫描覆盖全部层级，不因前层凑够数量而提前停止；扩展只运行零模型规则。全部规则合格事件先按URL身份和内容哈希进入 `discovery_queue`，未变化事件不再调用模型，内容变化事件重新开放。待筛队列不再把超过48小时的事件整体排到所有新线索之前，而是高分优先，并为外部补充、新鲜事件和久候事件分别留位。入模前再检查批次规模、来源数、高分事件数，以及“新鲜事件达到门槛”或“久候批次本身足够强”之一；低质久候批次不会仅因等待时间或 `--screen-now` 消耗模型Token，紧急事件和人工明确 `--force` 保留例外。`run_efficiency` 记录新增、重新开放、筛选前待处理、剩余待处理、模型输入和候选数，检查点另存模型前质量指标和暂缓原因。`scan-replay` 不新增模型调用；`--force` 仅供人工明确要求全量重算时使用。

## 发现漏斗与候选前影子核验

候选研究入口方法见 `docs/candidate_entry_trial.md`，日常Codex任务直接读取 `AGENTS.md`，隔离的初筛模型读取 `LiveDiscovery._model_rank` 内的实际提示。新运行使用 `fact_first_v1`：`materials.split_discovery_summary` 仅按显式边界标记将原350字摘要视图分为 `reported_excerpt` 和 `upstream_hypotheses`，未标记的推断仍可能留在前者，均不认证事实。规则筛选、历史匹配、冻结原事件和输出Schema不变。提示要求以材料为依据形成中性命题，容纳执行、政策衔接和风险路径，并报告决定性未知；不新增模型调用或自动放行逻辑。

既有 `screening_materials.json` 保存 `input_contract` 与有界 `model_input`，可核对实际送入模型的内容；升级前无版本字段的该文件表示 `legacy`，恢复仍构造原提示和输入以命中原缓存。新运行及同一版本续跑使用新契约，不重新研究旧停止题。报告将发现陈述、上游设想、模型意见和人工核验分列，实际推荐前由Codex依长期指令作少量回源；CLI不暗中追加网页抓取。人工入口记录仍用 `outputs/review/RUN_ID_scan_review.md`，占位文本不生成批准状态。此前的一条场景查询试行保持原配置，本次无数据库结构、预算、检索池或影子判定改变。

`collector` 在不保存网页全文的前提下，对每个来源记录RSS项数、时间窗内项数、元数据有效项数及解析错误。`discovery` 继续记录规则合格、规则排除、历史或同源排除、池容量截断、模型输入、模型入选和候选入选。每个排除阶段只保存 `[observability]` 设定数量的标题、URL和原因，避免把调试需求变成重型证据库。

`discovery_shadow` 在模型调用前对最多12条元数据识别事件角色、地方落点、是否直达一级原始页面，并与已核验政策机制匹配。非一级页面或未命中本地机制时，真实运行可在全局查询次数上限内做缓存的官方域名元数据搜索；不下载全文，不调用模型。相同运行和输入哈希复用已完成影子结果。影子建议只写库和报告，本版不将它传入规则分、模型输入选择、候选排序或阻断逻辑。

`outputs/review/discovery_observability_rolling.json` 只用真实 `live` 运行生成21天滚动对照。来源表从有效元数据、规则合格、模型入选继续回连到预研通过和最终成稿；达到最少真实运行数及至少14天观察跨度后，才可把连续零结果或长期无规则合格结果标记为 `degraded`，标签只触发检索词或抓取复核，不修改 `sources.toml`。影子政策覆盖评测只用后续预研明确的 `policy_covered`、`original_gap_supported` 和现有自动反馈作为决定性标签；普通 `reframe` 单独统计，不能被包装为覆盖命中。决定性后续样本不足时标记 `insufficient_followup`，样本达标也不能由程序切换为强制闸门、调整预算或删除来源。

## 扫描前维护

`preflight` 是零模型调用的只读预检，按 `scan`、`refresh`、`pre_research`、`research`、`writing` 分别核对SQLite完整性、残留任务、TOML解析、必需文件、写入目录、提供商、`.env` 权限和对应的单行为额度。后三个阶段必须传入 `run_id`，用于核验人工选题、人工深研放行或证据闸门，防止额度被用于未限定的扩题。`scan` 在筛选额度不足时仍可完成零模型元数据入队。`refresh` 默认零模型，因此不会因筛选 Token、调用成本或 Codex CLI 不可用而阻断。

Token默认观察策略由 `budget.enforce_token_limits=false` 控制。调用前预留和实际/未知用量、阶段/累计Token继续审计，均不因数值超过旧参考而暂停，超出参考的记录标记 `enforced=false`，不要求逐次提额。显式恢复策略仍可使用原上限与累计规则。调用次数、失败重试、超时、付费与Tavily边界保持独立，研究范围、证据与人工审批门槛继续执行。

`cleanup` 默认只产生带理由的清理计划。`--apply` 先调用SQLite backup API写入 `data/history/backups/`，再按外键顺序删除无价值运行数据和临时路径，最后 `VACUUM` 并运行 `integrity_check`。保留范围为所有真实运行、最新回放、提供商诊断、源数据、缓存、模板和耐久研究记录。真实运行的 `docx_qa` 中，编号最高的 `render-vN` 与 `fidelity-vN` 永久保留；其余版本超过配置的7天保留期后才进入预览清理，未知命名不自动删除。

## 状态机

`discovery → selection(needs_review) → incremental_review(needs_review) → research/pre-research(needs_review) → research(human proceed) → writing → export(needs_review/completed)`。

任一步骤可进入 `failed`、`paused_quota`、`paused_budget` 或 `skipped`。扫描已完成全部可用扩展层、队列没有待处理事件且未形成候选时，检查点必须写入停止原因并将 `next` 置为 `none`；普通小批量进入队列时，下一动作指向下一次 `sqmy scan`。暂停时保留原阶段和原下一动作；只有暂停或失败运行可以恢复。发现阶段使用 `scan --resume RUN_ID` 在同一运行继续。每次转换立即提交 SQLite 事务；JSON、报告和DOCX均先写同目录临时文件再原子替换。任务以 `run_id + kind + input_hash` 保证输入未变化时复用结果。

扫描以工作区级非阻塞文件锁防止双进程重复消费，进程退出后由操作系统释放。模型调用前固化 `scan_input.json`，已完成的制度审查固化 `scan_audits.json`；恢复只继续同一输入。模型结果与调用最终用量同事务保存，候选落库后才更新队列。即使原运行带 `--force`，同一运行已经完成的输入仍复用；跨运行缓存只在相同运行模式间共享，fixture不能给真实扫描提供模型结果。硬退出的 `running` 状态只可在取得锁后接管；无输入快照的旧运行保留兼容路径，不猜测缺失快照。

## 新鲜度复核与正式稿生命周期

候选在扫描后24小时内可直接进入有限预研；超过期限、事件快速变化或临近正式写作时，`refresh` 收集原扫描截止点后的受控来源元数据并进行规则初筛，记录输入哈希、数量、报告路径、零模型调用和人工决定。正式导出要求最近一次有效检查未超过期限；已有复核任务时必须由人工明确记录 `keep`，程序不会把“规则合格”直接等同于“建议替换”。

深研完成后，`draft` 接收固定三级结构 Markdown。只有候选已经人工选择、对应预研决策单已经人工放行且证据闸门通过时才导出送审DOCX。导出任务同时保存文件 SHA-256；同一题目改稿覆盖同名送审文件后，旧输入对应的任务标记为 `skipped`，只有输入哈希和现存文件哈希同时匹配时才复用缓存。`approve` 代表人工审核通过并进入待报送目录，不代表实际报送；`mark-submitted` 只登记人工已经完成的报送日期和层级，不执行发送、上传或报送动作。

## Token 控制

Token策略全部位于 `config/settings.toml`，默认观察不阻断；保留旧阶段数值供比较或显式恢复。程序请求按实报量/未知保守预留分列，主对话筛选及深研/写作按产物代理、预研按声明估算记账，均不是官方Token或账单。已记录估算不向下清零；阶段内幂等取最大，不覆盖完整上下文和推理，可能低估。来源池、时间范围、次数、超时、审批及费用边界保持。订阅额度或速率限制仍暂停。

每次提供商请求（包括备用切换）单独占用次数。`CallLedger` 使用 `BEGIN IMMEDIATE` 把行为Token/次数检查、同输入重试检查、近7日金额及未结算预留检查和本次登记合成一个短事务，事务提交后才请求外部服务，不在网络期间持有数据库锁。请求估算包括提示和Schema；费用按预计总Token乘较高单价保守预留。成功、解析失败和传输错误都核算；无法取得可靠用量时保留估算并独立展示，不冒充实测或归零。调用表增量添加 `accounting_method`、`response_id`、`error_code`，不改写历史记录。JSONL从该运行SQLite记录原子重建。

独立Provider调用硬退出可能发生在服务端完成与本地提交之间，不能保证跨服务恰好一次：预留、次数和未知费用保留，重试仍受请求次数及失败边界约束；Token累计仅观察（显式恢复额度策略时才拦截）。超出参考值或费用预留须记录，恢复不能抹去。对话导入从已接受结果续完，不重复判断或计账；旧备用诊断停用。

任何人工提高或降低预算均通过 `budget_adjustments` 记录阶段、原额度、新额度、原因和预期收益；完成后补录实际Token、实际收益及 `retain`、`revert` 或 `reassess`。命令只做审计，不自动修改配置。候选阶段只传标题、摘要和结构化元数据；深研只处理人工确认且预研放行的 1—2 题；写作只接收结构化研究摘要和已核验证据。

## 真实候选发现层

`collector` 从 `config/sources.toml` 的受控检索通道收集近90天标题、摘要、时间和原始URL。搜索RSS仅作为发现入口，Bing跳转链接会还原为来源页面；响应按查询哈希缓存，缓存小时数由配置控制，默认6小时，不批量下载正文。

全国部委和调查源的扩展使用有限并发的元数据检索，默认6个并发请求，不改变缓存、超时和来源审计语义。论坛与社交网站因登录、反爬和索引不稳定，通过 `--clues` 导入 Codex 受控网页检索的JSONL元数据。导入要求公开HTTP(S) URL和可验证发布时间，拒绝敏感查询参数，只将规范化线索快照保存到运行目录。

来源通道地域与事件实际地域分开保存。事件地域只依据可信地方域名或标题、摘要中的明确地域证据推断；“北京电”等媒体发稿地不会被当成事件发生地。地域判断依据保存在 `region_evidence`，便于复核。

`screener` 完成主题分类、活动宣传硬过滤、URL与相似标题去重和规则评分。采集结果先压缩为15—30条，再取8—12条进入模型层。默认 `provider=codex_cli`，在空临时目录中运行本机 `codex exec`；只读沙箱和提示不等于禁用全部工具，真实调用另须核实订阅认证、接收方与发送范围。2026-10-01用户决定停用DeepSeek：旧auto配置也只有Codex主通道，额度和速率限制暂停，不切换；DeepSeek直连、兼容客户端和旧备用诊断在请求前返回停用错误，不读取凭据。历史账本与通用测试路由兼容保留。Tavily能力保留，按需且在已确认无新增账单的额度内使用。每次真实模型尝试仍写入 `model_calls` 和运行级审计文件。

候选报告只输出最多5题；不足时允许少于5题，不以低质量事件补数。候选保留原始URL、来源等级、历史标题相似度和“不得直接报送”标记。

## 2026-09-20 摘要语义与目录日期修正

`screener.reported_text` 复用既有显式摘要分隔器，规则主题、分数、问题/证据信号、优先级及主主题只使用标题与材料陈述；地域推断、查询补缺计数及紧急批次触发也不读取待核假设。完整summary仍保留供模型分栏判断，不认证陈述为已验证事实；未明确分隔的旧摘要按原文兼容，不靠猜测删句。新扫描读取旧待筛队列时，对含显式假设的材料重新计算地域、主题及规则资格，只使用内存副本；原队列记录和已冻结运行不追溯改写。

公开答复目录日期不再声称是reply_date。published_at兼容保存原目录时间，provenance.date_basis与date_note说明语义；未回源时不填事件或答复时间。限定回源诊断在observed_dates分别保存来信/答复/发布/会议等日期，不将拟议生效时间认证为已生效。未新增正文批量采集或SQL结构。


## 当前对话筛选入口

`scan-prepare`复用原采集、历史/stop门、同源合并和事实/假设输入契约，冻结快照、提示、Schema、配置与实现哈希、有效期和停止状态；权威包保存在SQLite的 `conversation_screening_prepare` 任务，JSON为阅读副本。界面模型未知就记录unknown，不读取隐藏文件猜测。

主对话按Schema判断，Codex自动写出绑定信封并 `scan-import`。导入全量校验后先事务保存唯一的接受结果，再幂等记账和续完原评分/报告/队列流程；不同结果拒绝覆盖。导入和扫描共用fcntl独占锁，候选写入事务前再次检查停止及版本；候选阶段尚未完成时不能选择。收尾检查点保存接受哈希，即使最后任务标记失败，也不会重复重排或清除用户后续选择；`scan-import --resume`可从SQLite回执重建，不依赖原答案文件。

导入没有Provider或网络请求，原制度新意算法只读本地机制匹配，网络反证标为not_searched。少数题回源仍由Codex按既有规则完成。对话的冻结输入、Schema和结果长度只形成产物代理估算，官方用量为空；不插入虚构model_calls。实际主对话/本机工具桥接与质量效果尚待一次授权的有界真实运行验证。
