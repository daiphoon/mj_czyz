# 第一版技术设计

## 边界

当前版本保持单机 Python + SQLite 架构：候选发现可在任意日期由用户发起，受控公开来源先进入跨日发现队列，再由可审计模型分批初筛；超过新鲜度期限时采用零模型增量复核。深研和正式写作仍由人工与Codex协作完成，再由程序执行证据闸门、确定性DOCX导出和人工审核状态登记。不建设批量全文抓取、自动定时任务或自动对外报送。

## 模块

- `config`：TOML 配置和路径解析。
- `db`：SQLite 历史库、运行库、来源库、模型调用审计库。
- `workflow`：六阶段状态机、幂等候选生成、人工闸门、暂停和恢复。
- `budget`：任务预留和全周 Token 上限。
- `document`：从保留的参考 DOCX 创建显式样式模板并导出正式结构。
- `cli`：本地命令入口。

## 数据模型

`runs` 保存运行级检查点；`tasks` 保存幂等输入哈希和步骤结果；`candidates` 保存候选及分项理由；`topics` 保存历史选题以及送审稿、人工通过和实际报送状态；`sources` 保存轻量溯源、来源用途和最近核验时间；`claims` 保存正文可能使用的事实、推断、政策和制度新意主张及其认识状态；`claim_sources` 保存来源的支持/反证角色与原始信息链；`research_reviews` 保存有限预研决策单和人工放行；`model_calls` 保存调用前估算、实际Token、阶段上限和超限状态；`budget_adjustments` 保存预算调整的理由—收益闭环。`discovery_queue` 保存全部规则合格事件的最小元数据、内容哈希、首次及最近发现时间和待筛选状态；`source_funnel` 按运行和来源保存发现阶段数量；`discovery_exclusion_samples` 只保存各排除阶段的小量元数据样本；`discovery_shadow_reviews` 保存候选前影子核验及后续模型入选、候选入选对照。

## 有限预研决策闸门

人工选题后、深研前先生成小型结构化决策单。决策单明确区分已验证事实、基于证据的推断、未验证假设和分析判断，并记录最强反证、替代解释、关键未知、放弃条件、置信度、北京或海淀权限边界、定向研究问题和本阶段预算理由。`proceed` 与 `reframe` 仅代表结构化检查允许提交人工复核；存在阻断性关键未知时即使人工命令也不能越过。只有最新决策单的 `human_decision=proceed` 才能解锁对应运行、候选和题目组合。

每个初步机制以内部卡片记录行动主体、对象、触发条件、信息、成本承担、受益者、预期行为、规避、成本转嫁、核验、纠错、退出和更低成本替代方案，并分别压力测试基线、最可能和不利情形。该卡片不直接进入正式稿，避免正文任务蔓延。

## 证据质量闸门

深研不再只统计网页数量。每个关键主张都记录 `origin_group`：转述同一发布会、原报告或数据库的页面只算一个来源链。关键主张可由一个正式一级原始来源支撑，或由至少两个独立来源链交叉验证。零主张、零核心主张一律阻断；多个独立来源链优先标记为交叉验证，避免误报为“单一权威来源”。

制度新意主张还必须完成现行法规、政策、司法建议和主管机制覆盖审查。正式证据包中的主张需标注 `verified_fact`、`evidence_based_inference`、`unverified_hypothesis` 或 `analyst_judgment`。未分类主张、未验证假设和分析判断不能直接进入正文；核心主张还需保存置信度、截至日期、不确定性、可证伪条件和来源最近核验时间，核心统计需保存时间、地域、总体、单位和定义。状态为 `single_source`、`conflicted`、`needs_review` 或 `rejected` 的关键主张会阻断正式写作。详细元数据只在正式研究证据包强制，不把候选阶段升级成重型档案。系统允许深研结论为“不成稿”。

## 候选阶段制度新意快审

模型初筛不再直接产出最终5题，而是最多产出8个备选并为每题记录 `gap_hypothesis`、`gap_type` 和最多2条 `counter_queries`。`novelty` 模块先查已核验的本地政策机制库，再在真实运行中完成最小化的标题、摘要反证检索。区级 `site:` 查询会保留原查询并追加覆盖北京市和中央官方域名的跨层级查询；反证政策使用独立的730天窗口，不受候选新闻90天窗口限制，命中后先标记覆盖风险而不据此认定政策仍然有效。

自动阻断采用不对称规则：仅 `policy_absence` 类主张被本地已核验机制直接覆盖时标记为 `covered / block_original_gap`。执行、效果、协同和问责类主张即使命中既有机制，也只标记为 `likely_covered / keep_with_novelty_warning`，不自动删除。检索无结果只能得到 `unclear`，不能证明制度不存在。

`novelty_audits` 保存每次快审、决策、反证、复核结果和代理Token指标。有效预研通过候选中的事件ID回连快审记录，并按标准化 `decision_reason` 自动写入 `confirmed_block`、`confirmed_warning`、`false_block`、`missed_coverage`、`reframed`、`supported_gap` 或 `stopped_other`；已经存在的人工复核理由优先，自动反馈不得覆盖。每次扫描都会重新计算滚动21天指标。自动结论增加 `improve_early_coverage_detection`，用于样本量足够且后续预研发现早期漏判时提示修正规则。阻断准确率只使用能判断阻断正确或错误的标签，不把“改写”或其他停止原因混入分母，也不使用系统自己的阻断结果循环证明自己正确。

## 候选100分评分与自然周产出漏斗

规则初筛分只负责在模型调用前压缩事件池。正式候选分由 `[scoring]` 的八项正向权重计算，再扣除 `[penalties]` 及制度新意快审扣分；权重合计不是100时 fail-closed。海淀事件取得海淀分后不再重复取得北京分，时效分由发布时间确定，其余判断分由结构化初筛结果提供并受配置上限约束。候选 `score_reasons` 保存每项得分、满分、理由、扣分键、扣分值和依据，最终按综合分排序；旧模型缓存缺少新字段时按零分处理相应判断维度，不会回退使用规则分冒充综合分。

滚动质量报告按真实运行的发现周建立自然周 cohort，把后续选择、预研、深研、证据闸门、成稿、人工通过和实际报送归回该运行所在周，避免同一材料跨周处理时重复计数。报告保留每周停止原因、预研停止率、每篇证据闸门通过稿所需候选数和项目已记录Token。默认展示当前周加最近4个完整周；稳定产出只评价已经结束的4个自然周，漏跑周以零计，当前未结束周不提前计为失败。由于交互式Codex订阅通道可能不提供精确Token，报告显式区分项目账本记录量与不可计量部分。

## 模型调用前的去重与复用

`run_context` 区分 `live`、`test_fixture`、`mock`、`diagnostic` 和 `replay`，只有 `live` 运行进入历史排除和21天质量指标。规则筛选后的模型输入池会先核对历史URL、“标题+发布日”，以及“同日、同发布机构、同核心主题”的跨站转述，未变化或同源事件不进入模型。完整输入哈希相同时，`tasks` 跨运行复用已完成结果。缓存查找发生在预算预留和提供商初始化之前，因此零成本复用不受当前预算或备用密钥状态影响。初筛显式使用 `screening_model`。

每次扫描使用四层发现池：第一层为海淀和北京主题源，第二层为北京法院、检察、市场监管和权威媒体，第三层为全国部委、监管、司法、统计和调查源，第四层为投诉、论坛和社交平台待核线索。扫描覆盖全部层级，不因前层凑够数量而提前停止；扩展只运行零模型规则。全部规则合格事件先按URL身份和内容哈希进入 `discovery_queue`，未变化事件不再调用模型，内容变化事件重新开放。普通事件达到4条、等待48小时或命中紧急条件后才从队列中按来源多样性取最多12条初筛；人工 `--screen-now` 只提前处理队列，不绕过去重和预算。`run_efficiency` 记录新增、重新开放、筛选前待处理、剩余待处理、模型输入和候选数。`scan-replay` 不新增模型调用；`--force` 仅供人工明确要求全量重算时使用。

## 发现漏斗与候选前影子核验

`collector` 在不保存网页全文的前提下，对每个来源记录RSS项数、时间窗内项数、元数据有效项数及解析错误。`discovery` 继续记录规则合格、规则排除、历史或同源排除、池容量截断、模型输入、模型入选和候选入选。每个排除阶段只保存 `[observability]` 设定数量的标题、URL和原因，避免把调试需求变成重型证据库。

`discovery_shadow` 在模型调用前对最多12条元数据识别事件角色、地方落点、是否直达一级原始页面，并与已核验政策机制匹配。非一级页面或未命中本地机制时，真实运行可在全局查询次数上限内做缓存的官方域名元数据搜索；不下载全文，不调用模型。相同运行和输入哈希复用已完成影子结果。影子建议只写库和报告，本版不将它传入规则分、模型输入选择、候选排序或阻断逻辑。

`outputs/review/discovery_observability_rolling.json` 只用真实 `live` 运行生成21天滚动对照，按来源呈现漏斗产出，按影子建议呈现后续模型和候选入选数。同时满足最少真实运行数和至少14天观察跨度后才标记可比较，避免同一天重跑冒充2—3周样本。样本不足时标记 `insufficient_observation`；样本达标也只能用于比较相关性，不能由程序自动宣告影子规则有效、切换为强制闸门或调整预算。

## 扫描前维护

`preflight` 是零模型调用的只读预检，按 `scan`、`refresh`、`research`、`writing` 分别核对SQLite完整性、残留任务、TOML解析、必需文件、写入目录、提供商、`.env` 权限和相应预算。`scan` 在筛选额度不足时仍可完成零模型元数据入队，但会在模型前安全暂停；`refresh` 默认零模型，因此不会因筛选Token、调用成本或Codex CLI不可用而阻断。

`cleanup` 默认只产生清理计划。`--apply` 先调用SQLite backup API写入 `data/history/backups/`，再按外键顺序删除无价值运行数据和临时路径，最后 `VACUUM` 并运行 `integrity_check`。保留范围为所有真实运行、最新回放、提供商诊断、源数据、缓存、模板和耐久研究记录。

## 状态机

`discovery → selection(needs_review) → incremental_review(needs_review) → research/pre-research(needs_review) → research(human proceed) → writing → export(needs_review/completed)`。

任一步骤可进入 `failed`、`paused_quota`、`paused_budget` 或 `skipped`。扫描已完成全部可用扩展层、队列没有待处理事件且未形成候选时，检查点必须写入停止原因并将 `next` 置为 `none`；普通小批量进入队列时，下一动作指向下一次 `sqmy scan`。暂停时保留原阶段和原下一动作；只有暂停或失败运行可以恢复。发现阶段使用 `scan --resume RUN_ID` 在同一运行继续。每次转换立即提交 SQLite 事务；JSON、报告和DOCX均先写同目录临时文件再原子替换。任务以 `run_id + kind + input_hash` 保证输入未变化时复用结果。

## 新鲜度复核与正式稿生命周期

候选在扫描后24小时内可直接进入有限预研；超过期限、事件快速变化或临近正式写作时，`refresh` 收集原扫描截止点后的受控来源元数据并进行规则初筛，记录输入哈希、数量、报告路径、零模型调用和人工决定。正式导出要求最近一次有效检查未超过期限；已有复核任务时必须由人工明确记录 `keep`，程序不会把“规则合格”直接等同于“建议替换”。

深研完成后，`draft` 接收固定三级结构 Markdown。只有候选已经人工选择、对应预研决策单已经人工放行且证据闸门通过时才导出送审DOCX。导出任务同时保存文件 SHA-256；同一题目改稿覆盖同名送审文件后，旧输入对应的任务标记为 `skipped`，只有输入哈希和现存文件哈希同时匹配时才复用缓存。`approve` 代表人工审核通过并进入待报送目录，不代表实际报送；`mark-submitted` 只登记人工已经完成的报送日期和层级，不执行发送、上传或报送动作。

## Token 控制

预算全部位于 `config/settings.toml`。候选初筛同时受单次阶段上限、发现阶段7日上限、项目7日总上限和研究写作保护性预留约束。真实模型接入时使用固定开销和保守系数预估并预留预算，调用后写入估算值、阶段上限和实际 Token。由于订阅通道的单次在途调用不能可靠按Token中断，实际超限时先持久化有效结果和检查点，再将本运行置为 `paused_budget`，停止后续自动模型步骤；已经入队的事件不会丢失。额度错误进入 `paused_quota`。

任何人工提高或降低预算均通过 `budget_adjustments` 记录阶段、原额度、新额度、原因和预期收益；完成后补录实际Token、实际收益及 `retain`、`revert` 或 `reassess`。命令只做审计，不自动修改配置。候选阶段只传标题、摘要和结构化元数据；深研只处理人工确认且预研放行的 1—2 题；写作只接收结构化研究摘要和已核验证据。

## 真实候选发现层

`collector` 从 `config/sources.toml` 的受控检索通道收集近90天标题、摘要、时间和原始URL。搜索RSS仅作为发现入口，Bing跳转链接会还原为来源页面；响应按查询哈希缓存，缓存小时数由配置控制，默认6小时，不批量下载正文。

全国部委和调查源的扩展使用有限并发的元数据检索，默认6个并发请求，不改变缓存、超时和来源审计语义。论坛与社交网站因登录、反爬和索引不稳定，通过 `--clues` 导入 Codex 受控网页检索的JSONL元数据。导入要求公开HTTP(S) URL和可验证发布时间，拒绝敏感查询参数，只将规范化线索快照保存到运行目录。

来源通道地域与事件实际地域分开保存。事件地域只依据可信地方域名或标题、摘要中的明确地域证据推断；“北京电”等媒体发稿地不会被当成事件发生地。地域判断依据保存在 `region_evidence`，便于复核。

`screener` 完成主题分类、活动宣传硬过滤、URL与相似标题去重和规则评分。采集结果先压缩为15—30条，再取8—12条进入模型层。默认 `provider=auto`：主通道以只读、临时会话运行本机 `codex exec`，使用ChatGPT/Codex订阅；初筛在不含仓库文件和项目说明的空临时目录中运行，并由提示明确禁止工具和网络访问。只有明确的额度或速率错误才切换DeepSeek JSON API。普通失败不切换，避免掩盖程序或质量问题。每次结果均写入 `model_calls` 和运行级结构化审计文件。

候选报告只输出最多5题；不足时允许少于5题，不以低质量事件补数。候选保留原始URL、来源等级、历史标题相似度和“不得直接报送”标记。
