# RSS 获取异常修复与验证（2026-09-20）

结论：本地错误识别与反证失败传递已修复；Bing 新闻 RSS 的外部可用性仍被阻断，四层有效覆盖尚未恢复。不据此宣称本轮完成了采集入口恢复或 v3.0 正式验收。

## 已确认的问题与修复

原新闻 RSS 请求在本机网络下最终到达 `https://cn.bing.com/`，HTTP 200，内容为 HTML 首页。地区、语言参数及同服务域名变体也出现相同结果；这足以解释本轮解析失败，但尚不能判断重定向的服务端策略或网络成因。

原实现有两个本地问题：取得响应后未经验证就写入 RSS 缓存；反证解析错误在通用解析器中被吞掉，返回空列表。现已修复：

- 新 RSS 响应先检查 XML 和 `rss/channel` 结构，无效内容不写入缓存。
- 尚未过期的旧异常缓存明确报错，保留原文件，不额外请求；有效缓存继续复用。
- 批量发现保留来源错误，反证查询将解析失败交给既有审查错误分支。有效空 RSS 仍是成功空结果。
- 官方 HTML 目录继续使用原来的提取、日期和缓存规则，不被 RSS 校验误伤。

没有修改来源名单、检索词、候选排序、预算、模型或强制覆盖规则，没有改写历史扫描。原有政策机制库与研究文件未改动。

## 有界网络检查

本轮共 13 次顶层 HTTP 请求（自动重定向可能包含多个 HTTP 跳转）：8 次入口对比、1 次普通搜索结果核验、3 次其余来源层的代表性检查及 1 次反证入口检查。第一层复用了入口对比的结果。没有扫描全部 40 个 RSS 关键词，没有文章正文抓取、模型调用或付费搜索 API 调用。

新闻入口均未取得有效 RSS。普通搜索入口虽返回 XML，样本却包括百科、政府门户首页和问答页面，其 `pubDate` 不能据此认定为文章发布日期；没有将这些结果导入真实候选，也没有用它替换新闻入口。

四层检查是各层代表性查询的可用性检查，不是完整覆盖评估。诊断在临时目录使用真实配置，未连接真实业务库写入记录。审计只保留响应元数据与少量搜索摘要，未保存首页全文、Cookie 或凭据。
