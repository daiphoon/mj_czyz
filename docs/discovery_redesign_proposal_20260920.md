# 社情民意信息发现体系重构建议

日期：2026-09-20。性质：架构与研究方法建议，尚未实施。依据为当前代码、配置、最近运行记录及本轮公开页面核验；不启动真实扫描、不调用项目付费搜索API、不修改既有闸门。

后续状态：用户已批准实施，并补充Token以实际需要与质量为准、必要时扩大。以上及文末“本轮”保留建议提出时的历史口径；当前不再以相同或更低Token作为优化前提。

## 1. 需要解决的实际问题

目标应改为：在明确投入内，持续取得有公共价值、有具体材料、有研究路径的新问题，同时保留政策变化与前瞻性风险的发现能力。渠道可用、搜索结果多、候选分高都只是中间指标。

当前有40条 `rss_search`、5条 `html_index`，另有Tavily补充与Codex交互式公开线索导入。40条并非40个独立RSS订阅源，而是40组查询，统一由 `src/sqmy/collector.py` 的 `_fetch_query()` 拼成Bing新闻搜索RSS。配置中的政府、法院、媒体名称是查询目标，不代表直接连接了这些机构。共同入口失效会同时损失这些查询；反证检索也调用同一入口。

现有设计有低成本、统一解析的便利，但存在三个独立问题：获取集中、查询不能证明覆盖充分、材料以新闻为主。增加API供应商只能解决其中一部分。

还有一项统计口径需纠正：`src/sqmy/retrieval.py` 把全部Tavily发现记录的 `expansion_tier` 设为4，另行识别实际域名和信源等级。因此9月20日12条模型输入中9条归第四层，只能证明该补充入口占比高，不能证明9条全是投诉、论坛或低等级信源。历史统计不重写；新设计应另记真实材料类型和获取方式。

## 2. 旧四层的含义与局限

| 现有层级 | 实际定义 | 局限 |
| --- | --- | --- |
| 第一层 | 海淀、北京主题源 | 地域与主题混合 |
| 第二层 | 北京增补权威源 | 与第一层内容交叉 |
| 第三层 | 全国部委、监管、司法、统计和调查源 | 来源角色跨度很大 |
| 第四层 | 投诉、论坛、社交平台待核线索；实现中也承载Tavily补充 | 材料类型与获取入口混用 |

四层可作为兼容标签，保留北京优先、全国不漏和公众线索不被完全排除的意图，但不宜继续承担技术架构或覆盖验收的全部职责。每层都发过请求不等于有效覆盖，每层都找到候选也不应成为硬性指标。

建议把以下维度分开记录，不生成所有组合的庞大任务表：

- 地域：海淀、北京、全国及可比较地区；材料发生地与政策权限范围分开。
- 材料作用：具体问题、现行规则、执行与处理结果、统计背景、调查解释、反证。
- 获取方式：原站直连、原生订阅、站内公开搜索、跨站搜索API、交互式网页检索、人工提供。
- 发布者及原始信息链：找到的网页是谁发布、实际转述谁、同一报道是否多处转载。
- 研究入口：实际执行问题、规则衔接和适用边界、具有具体依据的前瞻性风险。

搜索服务不同，不代表证据来源独立；政府网站不同，也可能转载同一报告。以上记录先用于观察和检索调度，不顺带修改候选排序、信源等级或影子闸门。

## 3. 三种发现方式共同工作

### 3.1 持续查看高价值栏目，取得不依赖关键词的材料

维护一份精简的公开栏目清单，获取标题、原始链接、日期及必要短摘要，按更新节奏检查变化。优先栏目是具体办理答复、司法案例与建议、审计问题及整改、执法检查报告、调查报道、规则修订与征求意见。普通工作动态和门户首页的优先级较低。

有原站RSS/Atom就用原生订阅；没有则评估公开栏目HTML、公开站内搜索或站点地图。站点地图只能辅助发现URL，其更新时间不能自动当作文章发布日期。公开PDF报告先看目录和必要章节，不把全部附件批量下载、拆题或送入模型。动态页面和登录平台保留交互式或人工路径，不为每站建设复杂抓取器。

本轮公开核验的例子：

| 入口 | 可能取得的有用材料 | 本轮确认及限制 |
| --- | --- | --- |
| [北京市政民互动](https://www.beijing.gov.cn/hudong/) | 来信选登、部门答复、意见征集 | 页面可读，存在具体事项与答复日期；不能假设全部热线记录公开，咨询内容也不自动是制度问题 |
| [北京市人大报告栏目](https://www.bjrd.gov.cn/zyfb/bg/) | 执法检查、立法说明、监督报告 | 页面可读，有2026年条目；报告内容不都适合选题，须查对象、问题与处理进度 |
| [北京市审计整改报告解读](https://sjj.beijing.gov.cn/zwxx/zcjd/202511/t20251128_4309765.html) | 问题与整改阶段相互印证 | 原站页面可读，并链接正式报告；此2025年材料仅为渠道样例，不能作为新事件补位 |
| [最高法权威发布](https://www.court.gov.cn/fabu.html) | 司法解释、文件、数据及公开案例线索 | 栏目可读，存在不同年份条目；不能把所有条目看成近期事件，须挑对栏目 |
| 北京本地调查报道栏目 | 群众问题、办理过程、冲突各方与结果 | [市政府公开材料](https://www.beijing.gov.cn/srpc/yxgs/dxal/202608/t20260808_4814642.html)介绍了相关媒体栏目；具体可持续获取入口仍待逐项验证 |

这些是有依据的试验对象，不是“已全部接入”。本轮中国消费者报首页读取超时、一条最高法旧目录链接返回错误页、一条新华社目录未取得内容，都不能算入口验证成功。浏览工具可读也不证明本地采集器已经可用。

### 3.2 按明确问题主动检索，补足固定栏目看不到的内容

保留Tavily，但将查询的职责写清：查什么空白、希望获得哪类材料、结果怎样影响下一步。搜索用于补缺、扩展未知领域和定位原文，而非每天把所有主题重新搜一遍。

可选其他方式：

- Codex交互式网页检索：目前可直接用于有限探索、回源和新来源发现；记录查询与投入。不能假定独立CLI可调用同一个工具，也不能把订阅渠道当作无限免费资源。
- 原站公开搜索：已知发布机构、报告名称或案号时通常值得优先尝试，取得的是明确目标材料。
- [Brave Search API](https://brave.com/search/api/)：官方提供搜索API并宣称独立索引，可作为获取依赖分散的候选；本轮只核实产品能力，未测试本机接入及中文民生召回。
- [博查Web Search API](https://open.bochaai.com/)：官方展示中文查询、URL、摘要和日期字段，可列入中文场景对照；本轮未调用API，详细文档和价格页未成功读取，不宣称价格优势或底层索引完全独立。
- 其他搜索网站、平台内搜索：可保留交互式补充路径，是否自动接入取决于合法接口、访问条件、稳定性及真实增量。无需一次购入多个供应商。

建议最终采用“直连为基础、Tavily加一个通过中文样本测试的备用搜索渠道、交互式查漏”。新服务应占用统一行为总额度，不给每家单独增加一套搜索预算。Bing即使恢复，也只是可选入口之一。

### 3.3 从已有线索追到证据，并积累可重用的问题

对少数拟推荐题，沿报道里的原始发布者、报告名称、案例编号、规则名称和处理机关追踪。把“具体事实入口、当前规则入口、一个决定性未知、获取限制”写清。候选前仍只做已有授权范围内的有限回源，不提前批量抓全文或启动付费预研。

例如，一条报道指向人大执法检查报告，可直接查看报告中问题与处理措施，而不是再搜十种“某行业存在问题”。但报告说已整改，也不能自动推断问题消失；须核对整改对象、时间和可观察结果。

建立小规模问题观察清单，复用已有政策和研究：只有出现新事实、规则变化或可验证的新机制切口才重开，不因同一新闻换了标题而再次入模。用户提供的调研笔记、公开办理材料、稿件也是有效入口，保留原始版本和使用边界。

## 4. 查询设计需要改变，但不能预先宣称新词更有效

现有查询同时有三种风险：

1. “北京养老医疗政策”“site:beijing.gov.cn 政策”范围宽、容易返回发布与宣传；适合基础规则观察，不足以承担具体问题发现。
2. 多个对象和机制词塞进一条查询，可能偏向同时包含这些词的评论文章，遗漏使用日常语言的材料；不同引擎对布尔语法的支持须核验。
3. Tavily八组固定场景按当前材料中的关键词频次补缺、按日期轮换，已经优于完全随机，但并未按历史预研收益、实际证据路径或已成稿机制去重分配查询。

建议以“对象或场景＋一个核心过程＋一种观察结果或材料类型”写短查询，同一问题准备少数不同作用的变体，按计划选用，不展开所有组合：

| 查询目的 | 示例，均为待测试检索式，不是已存在问题的断言 |
| --- | --- |
| 中性了解规则和办理 | `北京 养老助餐 服务结算 办理` |
| 寻找具体困难 | `北京 养老助餐 补贴结算 退回` |
| 寻找群众实际用语 | `老人 助餐优惠 用不了 回复` |
| 寻找权威问题材料 | `养老助餐 审计 整改` |
| 检查其他解释和已有解决 | `养老助餐 结算 调整 办理答复` |
| 发现未列入固定主题的新问题 | 查看人大、审计、法院、调查栏目近期更新，不预设行业关键词 |

不能每次都把所有词和所有查询执行一遍。例子只是展示方法；新场景是否有真实材料须通过样本核验。使用具体文号、报告名后应优先精确定位；缺结果时先放宽一个条件，而非同时换对象、时间和地区。全国有价值问题不强加“北京”检索条件。

保留三类研究入口：发生的问题、规则衔接、前瞻性风险。不能因加强问题检索而只追投诉；对政策变化须说明受影响对象、接口和可反证的风险路径，不能由新政策直接推导制度缺口。

时间也应区分文章发布、事件发生、规则生效和本次核验。新线索继续沿用现有90天窗口；现行规则、历史案例及年度报告作为背景和比较材料不被机械扔掉，也不能占用新事件名额。后续如采用7—30天增量查看，仅是减少重复浏览，不是悄悄收窄90天资格范围。

## 5. 有限预算下怎么分配

先保留现有模型、搜索次数与金额闸门，不用增加模型输入数量弥补低价值原料。新增来源主要增加少量本地元数据处理；先按原规则去重、排旧、比对已完成课题，再从原有8—12条模型输入上限内取材。不改变候选前政策覆盖影子模式。

建议试验顺序：

- 先看有更新的直接栏目，低频年报与法规目录按发布节奏查看，不每轮全部重抓。
- 四个付费发现查询槽位按缺口分配：一个本地缺口、一个全国或未覆盖领域、一个具体场景、一个开放探索；它们是初始试验安排，不是强制每轮用满。
- 先对查询结构做小样本核验，再比较Tavily basic与advanced。官方文档说明basic为1积分、advanced为2积分，不能由价格差推出质量相同。[Tavily文档](https://docs.tavily.com/documentation/api-reference/endpoint/search)
- 如果对照支持，4次全advanced的8积分可试改为2次basic加2次advanced，共6积分，仍是4次查询。按项目当前每积分0.008美元折算，分别是0.064与0.048美元；这是成功搜索的等价费用测算，不含提取、失败未知用量、订阅Token和人工时间，不是账单。当前参数未改变。
- 当前代码共用搜索深度，逐查询分配需要以后明确实现；不能把建议写成已有功能。新供应商费用使用统一金额账本，服务商积分仍分列，不能把不同单位直接相加。
- 已选题后的政策核验使用general等适当模式及原研究行动预算；不在未选题前悄悄增加付费预研。
- 候选数量足够但缺证据路径时，应完成有限回源而非继续增加搜索；预算耗尽、连续只有同源转述、决定性材料不可得时保存并停止。

获取计划执行前冻结查询目标、变体、渠道顺序和有界失败分支；每次实际请求先占额、记录结果与新增信息。故障不允许换运行ID继续同一被阻断行为；未知用量不归零。传输故障可在批准的策略内临时停止本轮同一入口的重复请求，保留未执行记录，不因短期健康表现自动删除发布者或降低信源等级。

## 6. 比较什么方案

| 方案 | 能解决什么 | 主要不足 | 判断 |
| --- | --- | --- | --- |
| 只修Bing | 恢复原查询 | 依赖集中、新闻偏向和查询问题仍在 | 不作为主方向 |
| 40条词同时发给多引擎 | 部分补召回与容错 | 付费和重复结果增加，不能保证独立原始材料 | 不建议 |
| 直接栏目＋有目的搜索＋有限追溯 | 同时改善获取依赖、材料种类和证据路径 | 需要少量栏目维护及查询复盘 | 推荐 |
| 全网爬虫、向量库和复杂代理群 | 可能扩大采集量 | 当前没有证据证明维护和调用成本值得 | 暂不建设 |

## 7. 分步实施与验收

### 第一步：重画来源与查询清单

把40组查询、5个目录、Tavily和人工导入映射到发布者、材料作用、获取渠道、地域与故障依赖。先形成可审查的清单和小样本测试方案，不改自动排序。选择约8—12个互补公开栏目作首批验证对象；这是工作范围上限建议，不是已经证明的最佳规模，也不要求每个都接入。

验收看实际条目能否取得日期、原始URL、材料类型及公开获取路径，尤其是“具体问题＋答复或整改”的内容。应含本地与全国、规则变化与执行材料，不能以门户首页HTTP 200代替验收。

### 第二步：分开验证渠道和查询

先固定查询与取材上限，对比现有搜索与一个备选服务；再固定服务，对比旧查询与新查询，避免同时换源、换词、换深度而无法解释结果。可准备8个查询任务，其中4个有已知原始材料、4个为新的探索任务；已知材料只测找回能力，不代表全网召回率。

付费对照如果需要，必须列出明确供应商、请求数、每次上限和总额另行形成可执行授权范围；不能伪装为普通四次扫描。无凭据时先完成直接目录和已有交互工具可验证的部分。本轮没有执行此对照，不能给新引擎排名。

### 第三步：小范围接入并运行一次真实发现

只接入验证过的少数渠道，复用当前本地Python、SQLite、缓存、发现账本、调用账本与冻结恢复机制。对已验证渠道分组运行，减少共同故障重复请求；保留原来源身份和历史记录。旧四层标签兼容读取，新统计增加独立维度。

按原预算完成一次真实发现，再对少数拟推荐题回源。不要等整个来源库全部完善后才生产，也不以产出新稿作为一次渠道试验必须达到的承诺。所有选题、预研、深研和人工送审门槛保留。

### 第四步：按新增价值决定扩展

先复盘一次运行的可用性，达到现有滚动窗口与观察跨度后再判断稳定收益。优先看：

- 新增独立问题簇，而非新增网页或转载数量；
- 原文可达率、真实日期可确认情况、重复或旧闻比例；
- 少量回源后值得预研的题及明确核验路径；
- 下游预研停止原因，区分证据不足、既有政策覆盖、没有新机制、权限不足；
- 单个有效研究入口所需请求、搜索费用、模型Token及实际记录的人工时间；
- 某搜索入口失效后，是否仍能从不同发布者取得本地与全国、执行与规则等互补材料。

正式推荐率不是唯一目标：正确排除已解决或证据不足的问题也有价值。缺乏研究产出时不把“零条成稿”转换成虚假效率数字。依然只有连续四个完整自然周达到现有口径才能宣称稳定周产量。

## 8. 本轮结论与边界

优先工作应改名为“发现体系重构与小样本验证”。目标不是40条RSS恢复，而是用相同或更低投入取得更有研究价值、能够追到原始材料的信息。渠道接入、查询设计、后续证据获取应一起规划，分开试验。

本轮只新增此建议文件：没有新增搜索供应商、调整预算、修改来源配置、启动扫描、导入候选、重开旧题或对外发送。公开网页核验和代码阅读不能证明某新方案已经提高成稿率。现有程序没有改动，沿用上一轮334项通过的程序验证，不把它称作本方案效果验证。
