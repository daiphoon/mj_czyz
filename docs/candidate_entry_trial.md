## 正常入口中的持久行为

本轮固化复用既有验收、候选转化诊断及 `outputs/review/fact_trial/2026-09-07-144b7f11/C1/result.md`。已确认的是上游摘要曾混入缺口设想、初筛模型只收到程序提示；未确认的是这是否主要导致低转化，以及中性命题是否提高研究收益。C1回源取得处理结果后仍因证据不足停止；既有C02成功也不能证明新方法有效。旧停止、审批及成稿记录不因本方法改写。

正常启动方式保持不变。`AGENTS.md` 约束Codex整理线索、推荐及研究接续；`sqmy scan` 和兼容入口 `monday` 的实际初筛提示负责输入解释。手工摘要沿用同一个 `summary` 字段，写成“材料陈述：报道中谁遇到何事，如何处理，有何分歧。待核假设：仍须查明的问题。”不把解释混进报道事实，也不要求RSS自动生成这两个标签。

程序只将显式标注的“可核验缺口是：”“待核假设：”“缺口假设：”“待核问题：”“原因推测：”“建议切口：”等段落分出；原350字视图总长不扩大，原事件和历史哈希不改。没有标记或分隔前夹带的推断不会被语义识别，`reported_excerpt` 仍是待回源材料。初筛提示要求中性标题、具体材料依据和决定性未知；候选报告不把这种分隔当核验通过。

发现问题可以沿三条路径：具体事件及执行问题；有具体条款或主体接口的政策衔接问题；由规则、技术或交易变化触发的前瞻性风险。后两者核对变化、受影响对象及可反证机制，不以缺少投诉直接淘汰，也不虚构已发生损害。当前不新增检索词或来源；现有池不足以支持其中某一路径时明确证据限制，不凑题。

新运行在 `screening_materials.json` 留下 `fact_first_v1` 和实际有界输入；旧文件无版本则按 `legacy` 恢复，避免丢失原提示缓存。离线fixture使用同一CLI接线但结果不进入真实质量指标。单独执行CLI仅完成初筛，不等于已执行下面的Codex内容核验。

## 人工推荐的研究入口

自动报告中的缺口与推荐均为模型判断。Codex在向用户正式推荐前，在既有 `outputs/review/RUN_ID_scan_review.md` 中按候选编号填写下表，自动报告中的占位项不算完成核验。复用已读政策与历史证据；仅有元数据时明确标注待核，不靠另开一轮无边界研究填满表。

只对少数拟推荐题回源，数量不超过 `project.max_formal_topics`；先查已有证据与缓存，再在本行为剩余额度和已有授权内读取原材料中决定判断的段落、时间和处理结果。必要时核对有对应关系的权威调查或脱敏结论，记录替代来源与原事件的关系；获取失败不凭摘要补齐。未选题前不运行付费预研 `retrieve`，不另开action补足额度；授权或预算不够时只报告待核线索和限制。现行政策优先复用已核且仍适用的记录，未复核的有效性或边界写待核。这里不要求完整合同、全来源阅读全文或提前完成机制压力测试。

| 项目 | 必须交代的内容 |
| --- | --- |
| 具体事实 | 谁在办理什么事，在哪一步受阻；来源、事件时间与报道时间，哪些已核实、哪些仅是陈述 |
| 现行机制和历史增量 | 已有规则及适用边界，旧题用过什么证据，此次新增什么；缺乏增量时直接说明 |
| 待证问题和证据入口 | 要取得什么材料、从哪个公开来源或经用户授权的调研渠道取得、回答哪个问题；尚无可信路径则只保留线索 |
| 推荐理由 | 主选、备选或仅保留线索；为什么值得投入，何种反证出现时放弃；质量允许时主选1题、备选1题，不凑数 |
| 实际投入与限制 | 本次请求、缓存/历史复用、既有action与剩余额度；获取、公开性或预算限制，不把占位表当作核验结果 |

不能从新闻出现困难直接推导“缺少制度”，也不以标题相似或存在政策直接淘汰。官方案例、调解材料、调查与公开服务规则可以提供事实链，不机械要求先取得全部私人合同和原件。没有新失败案例不能证明执行充分；旧案例可以说明机制，但必须核准当前适用性。

已有政策覆盖原说法时，做一次有边界的改写判断：究竟是适用范围遗漏、已定义义务的执行偏差、跨主体交接失败，还是人员与资源供给不足。只有事实支持才收窄题目，不连续换切口救题。该判断在现有阶段预算内完成，不触发新调用额度。

## 有限预研与深研边界

有限预研先确认问题真实且有公共价值、有权主体与可信证据路径，明确最强反证和停止条件。核心问题真实性、关键权限或决定性证据路径仍站不住时，继续stop。

人工选择后用一份共同事实材料比较原缺口与至多一次有依据的中性重构，分别列出多加的假设、最小决定性材料和建议继续/停止的理由，不为两个版本重复检索。原始网页获取受限时可用有对应关系的公开调查、脱敏处理材料，注明证明范围；既有救济及个案办结须记录为反证，但不能据此单独推翻事前预防问题。旧停止题重开仍须新授权和新证据或明确纠错依据。

前提成立后，具体适用范围、成本、行为反应、反证核验可以作为深研任务；每项写明材料入口、核验方法和失败后的处理。建议是否最终有效通常需要试点观察，不把“未先证明有效”单独当作否定研究的理由。涉及明显不可行、重大副作用或权限不成立时仍阻断。不更改程序对blocking字段的判定，不为放行改标签。

“适用范围”若决定该主体是否有权行动，就是预研前提；前提已核准后的对象细化才可留给深研。记录应明确取得证据支持继续、取得反证支持停止、或因获取/公开性/预算限制未完成核验；政策增量不足与获取失败分开，不把停止本身宣称为成稿能力改善。

深研围绕一个可证伪问题形成事实和机制判断，随后才建立主张—来源记录、通过证据闸门、写作及四项内容审查。用户选择候选不等于批准深研，人工批准深研不等于批准正式报送。

## 复盘与回退

从改动后的下一次正常扫描开始，在随后3次用户发起的真实扫描中记录该组是否被选中、是否实际请求或命中缓存、独有有效线索、人工推荐、预研结果及原因、后续深研支持和合格送审稿。沿用检索调用、来源漏斗和阶段反馈；人工推荐状态写在同一复核文件，不新建统计系统。

第三次扫描结束作初步复盘；深研或写作未结束的标为待观察，未抽到该组标为未暴露，不伪造零转化。Token实测与交互式阶段估算分列，成稿以首次合格导出记录及实存文件为准。

重点观察停止是否仍来自基本事实不清、旧证据无增量或没有核验路径，不能只比较候选数量。检索词调整与人工推荐改进分别记录，不能把联合变化归因于单一因素；小样本不声称因果或稳定产量。复盘给出retain、revert或reassess建议；若退回检索词，只恢复上面的原query，保留历史审计和研究结果，不自动调整预算、影子规则或其他来源。

本次输入和接续方法另记暴露版本，观察事实支持、政策增量、错误放行（含把待核前提当成深研任务）、研究价值及实际投入。离线同材料比较只能验证信息呈现和判断边界，不能证明模型采纳率或成稿率提高。当前保持小范围观察，不启用新的语义硬闸门。持久改动验收、任务范围补丁和回退步骤见 `outputs/review/workflow_persistence/2026-09-07/acceptance.md`；恢复程序行为时保留试验记录和原审批。
