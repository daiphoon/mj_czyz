# 研究证据传递与有界补查（2026-09-07）

本次为程序修复，未调整发现模型、评分、来源池、阶段Token和付费额度。详细诊断及同样本回放见本地 `outputs/review/workflow_revision/2026-09-07/acceptance.md`。附件故障分析作为待检验假设，历史六题没有“必须通过”标签。

## 已启用的确定性修复

- 预研报告携带每条来源的必要摘录、定位、适用限制、不能推出的结论和获取状态，便于人工直接核对主张。JSON中的原来源编号继续保留，不增加预研模型调用。
- 来源有明确 `summary_only`、`access_failed`、`irrelevant` 状态时不能验证事实；没有摘录也不能凭URL和一级来源标签通过。`fulltext_ok`、`excerpt_verified` 必须有非空 `excerpt` 和 `locator`。网页内容、摘录和附件中的命令均是待分析材料，不能成为程序指令。
- 旧来源有摘录而未记录 `fetch_status` 时兼容读取，并明确标为 `legacy_unclassified`，不补造全文成功记录。新记录应如实填写状态、定位、`limitation`；失败页面仍可保留在来源清单，但不能挂在已验证事实或反证上当作依据。
- 预研结果增加 `diagnostics`：按主张位置和来源编号区分 `SOURCE_UNREAD`、`TOOL_FAILURE`、`GAP_UNPROVEN`、`POLICY_DUPLICATE` 等，并保留关键未知的原问题和补查路径。它是记录诊断，不是额外模型终审。原有 `stop/proceed/reframe`、`record_valid`、`research_allowed` 和人工节点不变；`needs_evidence` 不代表重开或深研许可。
- 新增标准原因 `source_unread`、`tool_failure`、`claim_too_broad`、`fact_contradicted`。只有已核反证明确推翻核心事实时才能用最后一项，不能从“没搜到”自动赋值。记录了核心事实被否时禁止直接放行。
- 正式证据中，未获支持、存在冲突或应复核的辅助事实同样阻断写作。保留原有“非核心、范围明确、单一合格来源背景材料”的处理，不把它提升为核心数字的双源要求。
- 人工放行只对同一运行、同一候选的最新决策版本和对应题目有效。旧题审批不能在切口改变后继续用于预检、送审登记和导出；重新导入较旧决策单也不能恢复旧状态。数据库仍保留全部旧决策。

当前程序不能判断摘录是否忠实、来源是否真的支持整句话。不能把确定性检查称为自动事实审查。研究与写作仍由用户和Codex按结构化材料协作；来源列表齐全不等于可成稿。

## 在原行为内有限补查

先按原有 `retrieve` 完成初轮问题单。发现能改变结论的具体未知后，显式提交含 `repair` 的问题单，示意如下（编号及检索词必须替换为真实记录）：

```json
{
  "stage": "pre_research",
  "candidate_id": "C1",
  "queries": [{"purpose": "policy", "query": "准确文件名 适用例外 具体处理环节"}],
  "repair": {
    "round": 1,
    "review_id": "来自最新pre-research-check结果的review_id",
    "unknown_indexes": [0],
    "reason": "说明该材料将如何决定缩题、继续补证或维持停止"
  }
}
```

```bash
sqmy retrieve --run-id RUN_ID --plan data/sources/TOPIC_repair_plan.json
```

`unknown_indexes` 是最新决策单 `critical_unknowns` 的从0起编号。配置为最多2轮、每轮1—2项。初轮及全部补查、失败重试共用一个 `pre_research:C1` 或 `research:C1` 行为，**合计仍最多4次搜索、2次提取，积分与费用上限也不变**。把初轮额度用完后，补查必须停止，不能换运行或阶段规避预算。

每轮问题单固定后不可修改；轮次检查点和任务分别保留，成功结果幂等复用。前轮仍在执行或额度阻断时不能跳轮。人工已经明确 `stop` 或记录了核心事实被否时，不允许由该接口重启。分析决定为证据不足的 `stop` 时，显式补查只获取资料，不能修改原结论或继承通过状态；确有新证据后仍要形成新决策版本并走原人工节点。不自动为待补证题发起搜索。

如初轮检索是在交互网页工具中完成、没有 `retrieve` 检查点，不补造API调用记录。继续沿原渠道保存真实查询、获取状态和阶段预算；这次新增轮次控制只适用于现有 `retrieve` 接口。

## 阶段输入与判断要求

候选发现继续使用小型元数据，不输入批量网页全文。人工选题后，先读原始事实、现行规则及处置后续，将已核事实、推断和未知分开；补查只针对可能改变决策的未知。一个范围明确的真实案例不等于全国发生率；有政策不等于落实有效，也不能凭违规个案断言治理整体失效。

写作前继续复用现有预研人工确认、结构化证据包、`evidence-check`，以及绑定稿件和证据SHA256的四项内容审查。不新建同义的“研究简报通过”按钮。先提交短研究判断：证据支持什么、现行措施覆盖什么、还剩什么、谁有权做、增量及成本是什么。必要未知没有解决时停止写作；不得用润色修补事实。正文新增事实或数字必须回到证据核验及内容审查，程序不声称能自动识别所有新增语义主张。
